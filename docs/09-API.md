# 09. Правила API

Схемы запросов и ответов описаны **один раз** в `packages/contracts` и используются серверной проверкой, файлом OpenAPI и сгенерированным клиентом. Ручное написание клиентского кода обращения к серверу запрещено (`00-КОНТРАКТ.md` § П-2).

---

## 1. Общие правила

| Правило | Значение |
|---|---|
| Основание пути | `/api/v1` |
| Кодировка | UTF-8, `application/json` |
| Имена ресурсов | Существительное во множественном числе, kebab-case: `/org-units`, `/daily-summaries` |
| Имена полей | camelCase: `occurredAt`, `ownerOrgUnitId` |
| Время | ISO 8601 с суффиксом `Z`, всегда UTC |
| Идентификаторы | Строка `uuid` |
| Числа с плавающей точкой | Только для координат и площадей. Денежные суммы — строка десятичного числа, чтобы не потерять точность |
| Версия | Одна, `v1`. Вторая версия появляется только при несовместимом изменении и требует записи о решении |

**Смена состояния — отдельный подресурс, а не поле в теле изменения.**
Правильно: `POST /incidents/{id}/transition` с телом `{ "to": "registered", "reason": null }`.
Неправильно: `PATCH /incidents/{id}` с полем `status`. Изменение состояния требует проверки допустимости перехода и отдельного разрешения (`04-ДАННЫЕ.md` § 10).

## 2. Ответ и ошибки

Успешный ответ возвращает объект ресурса или объект со списком. Оболочки `{"data": ...}` вокруг успешного ответа нет.

Ошибка — всегда один и тот же вид:

```json
{
  "error": {
    "code": "ACCESS_DENIED",
    "message": "Этот объект существует, но не входит в вашу область видимости. Если доступ необходим для работы, обратитесь к администратору региона.",
    "details": {},
    "requestId": "01JC7Z0K8Q9V2M4N6P8R0T2W4Y"
  }
}
```

Коды и соответствие HTTP — `03-АРХИТЕКТУРА.md` § 5.3.

Содержимое `details`:

| Код | `details` |
|---|---|
| `VALIDATION_FAILED` | `fields`: массив `{ "path": "occurredAt", "message": "Дата не может быть в будущем" }` |
| `ACCESS_DENIED` | `permission`: код требуемого разрешения, если отказ по действию; отсутствует, если отказ по области видимости |
| `LIMIT_REACHED` | `limit`: ключ предела, `current`, `max` |
| `PRECONDITION_FAILED` | `currentVersion`: текущая версия объекта |
| `CONFLICT` | `reason`: машинный признак причины |

**`message` всегда на русском и всегда пригоден для показа пользователю без переработки.** Клиент не составляет тексты ошибок сам, кроме сетевых сбоев.

## 3. Списки

### 3.1. Постраничный вывод

Курсорный. Смещения (`offset`) не существует: на 500 000 строк оно работает недопустимо медленно.

```
GET /incidents?limit=50&cursor=eyJvIjoiMjAyNi0wOS0wOFQxMDowMFoiLCJpIjoiMDE5..."
```

```json
{
  "items": [ ... ],
  "nextCursor": "eyJvIjoi...",
  "total": 1234,
  "totalIsExact": true
}
```

- `limit` по умолчанию 50, предельно `LIMIT_LIST_PAGE_SIZE` (200). Большее значение — `LIMIT_REACHED`.
- `nextCursor` отсутствует, если страница последняя.
- `total` считается отдельным запросом с ограничением 10 000. При превышении возвращается `total: 10000` и `totalIsExact: false`; интерфейс показывает «более 10 000» (`07-КОМПОНЕНТЫ.md` § 5.5).
- Курсор непрозрачен для клиента: его нельзя разбирать и составлять.

### 3.2. Условия отбора

Явные именованные параметры для каждого ресурса. Общего языка запросов не существует: он открывает путь к произвольным выражениям и к внедрению SQL.

Общие для всех реестров:

| Параметр | Значение |
|---|---|
| `q` | Полнотекстовый поиск |
| `orgUnitId` | Подразделение |
| `includeDescendants` | `true` — включая нижестоящие; по умолчанию `true` |
| `sort` | `поле:asc` или `поле:desc`; допустимые поля перечислены в схеме ресурса |
| `limit`, `cursor` | § 3.1 |

Параметры реестра событий: `occurredFrom`, `occurredTo`, `kindItemId` (несколько значений), `scaleItemId`, `causeItemId`, `status`, `onlyEmergency`, `hasCasualties`, `registeredFrom`, `registeredTo`.

Неизвестный параметр — `VALIDATION_FAILED`, а не молчаливое игнорирование. Игнорирование опечатки в имени условия отбора приводит к тому, что пользователь видит не те данные и не знает об этом.

### 3.3. Область видимости

Применяется сервером ко всем спискам всегда (`05-ДОСТУП.md` § 4.5). Параметра, отключающего её, не существует.

## 4. Изменение данных

### 4.1. Идемпотентность

Каждый `POST`, создающий объект, **обязан** содержать заголовок `Idempotency-Key` со значением `uuid`, сформированным клиентом.

- Повтор с тем же ключом и тем же телом возвращает ранее сохранённый ответ и тот же код состояния.
- Повтор с тем же ключом и другим телом — `CONFLICT`.
- Срок хранения ключа — 24 часа.
- Отсутствие заголовка — `VALIDATION_FAILED`.

### 4.2. Одновременное изменение

`PATCH` и `POST .../transition` обязаны содержать заголовок `If-Match` со значением текущей версии объекта. Несовпадение — `PRECONDITION_FAILED` с текущей версией в `details`.

### 4.3. Частичное изменение

`PATCH` принимает только изменяемые поля. Поле, переданное со значением `null`, устанавливается в «нет данных»; поле, не переданное, не изменяется. **Это различие обязательно** (`04-ДАННЫЕ.md` § 8, пункт 4).

### 4.4. Защита от подделки межсайтовых запросов

Каждый изменяющий запрос содержит заголовок `X-CSRF-Token`, совпадающий со значением одноимённой cookie. Несовпадение — `UNAUTHENTICATED`.

## 5. Файлы

```
POST /blobs                     multipart/form-data, поле file
  → { "id": "...", "sha256": "...", "size": 123456, "contentType": "..." }

GET  /blobs/{id}/content        встречный поток, проверка прав по ссылающемуся объекту
```

- Предел размера — `LIMIT_UPLOAD_SIZE_MB`; превышение — `LIMIT_REACHED` **до** приёма тела запроса.
- Недостаток места — `LIMIT_REACHED` с ключом `LIMIT_DISK_FREE_GB`.
- Отклонение проверкой (`BLOB_SCAN_COMMAND`) — `CONFLICT` с причиной.
- Прямой доступ обратного прокси к каталогу хранилища отсутствует: файл выдаётся только через API.
- Загруженный, но ни к чему не привязанный объект удаляется заданием через `BLOB_GRACE_DAYS`.

## 6. Фоновые задания

Долгое действие возвращает `202` и идентификатор задания:

```json
{ "jobId": "0193...", "status": "queued", "queuePosition": 3 }
```

```
GET /jobs/{id} → { "status": "queued|running|done|failed",
                   "queuePosition": 2, "progress": {"done": 4210, "total": 50000},
                   "resultBlobId": null, "errorText": null }
```

- `progress` — доля обработанных **единиц работы**, а не готовности задачи. Это единственное место, где допустимо процентное отображение (`07-КОМПОНЕНТЫ.md` § 7.14).
- По завершении создаётся уведомление.
- Предел времени — `LIMIT_JOB_RUNTIME_MIN`; при превышении задание прерывается с понятной причиной.

## 7. Веб-сокет

```
WS /api/v1/stream
```

- Адрес соединения клиент выводит **из адреса текущей страницы** (`window.location`), а не из настройки и не из строки в коде. Иначе переезд на другой домен потребовал бы пересборки клиента.
- Проверка подлинности — по той же сессионной cookie. Отдельного маркера нет.
- Сообщение: `{ "channel": "incident", "event": "created", "entityId": "...", "at": "..." }`.
- Полезная нагрузка ограничена видом события и идентификатором. Данные клиент запрашивает обычным методом API. Причина — ограничение `LISTEN/NOTIFY` в 8000 байт и нежелание дублировать проверку прав в двух местах.
- Подписка проверяется по правам: на канал объекта подписан только тот, кто имеет право его видеть.
- При обрыве клиент переподключается с возрастающей задержкой (1, 2, 4, 8, 16, далее 30 секунд). После восстановления клиент перезапрашивает данные открытого экрана.
- Отсутствие соединения не ломает работу: уведомления видны в списке, данные обновляются при действиях пользователя. Индикатор состояния соединения в шапке обязателен.

## 9. Генерация и проверка

1. Схемы запросов и ответов пишутся на Zod в `packages/contracts`.
2. `pnpm gen:openapi` формирует `packages/contracts/openapi.json`.
3. `pnpm gen:client` формирует типизированный клиент в `apps/web/src/api`.
4. `pnpm check:generated` в составе `pnpm verify` завершается с ошибкой, если сгенерированные файлы отличаются от закоммиченных.

**Написание запроса к серверу вручную, минуя сгенерированный клиент, запрещено правилом линтера.**

---

## 10. Правила, которые нельзя нарушать

1. Каждый изменяющий метод порождает **ровно одну** запись журнала действий в той же транзакции.
2. Каждый метод списка применяет область видимости.
3. Ни один метод не возвращает идентифицирующие персональные данные без соответствующего разрешения — это обеспечено правами базы, а не проверкой в коде.
4. Ни один метод не выполняется дольше 5 секунд синхронно. Долгое — задание.
5. Ответ об ошибке не содержит стека вызовов, имён таблиц и текстов SQL.
6. **Ответ не содержит абсолютных адресов системы.** Ссылки на объекты передаются относительными путями, начинающимися с `/`; полный адрес собирает клиент (принцип П-5).
7. Метод, не описанный в этом документе, не создаётся.
