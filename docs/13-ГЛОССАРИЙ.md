# 13. Глоссарий

Единый язык системы. **Одно понятие — одно русское слово, один идентификатор в коде, одно имя таблицы.** Синонимы запрещены: расхождение терминов в интерфейсе, коде и документах — то, с чего начинается расползание проекта.

Если нужного понятия здесь нет — его нельзя ввести самостоятельно. Это вопрос Держателю контракта.

---

## 2. Понятия документов комплекта

| Термин | Значение |
|---|---|
| Держатель контракта | Единственное лицо, разрешающее противоречия и утверждающее изменения комплекта |
| Исполнитель | Модель, строящая систему по комплекту |
| Допущение | Утверждение о заказчике, принятое без подтверждения, с указанием способа проверки и замены |
| Приёмочный сценарий | Действие пользователя с наблюдаемым результатом, существующее в двух видах с одним номером |
| Норматив | Числовое требование к производительности с указанным способом замера |
| Архетип экрана | Один из шести способов собрать экран |
| Правило замещаемости | Запрет ветвления логики по значению кода элемента справочника |
| Ворота этапа | Условия, при которых этап считается пройденным |
| Локальная среда исполнителя | Первая из трёх сред: контейнеры на машине Держателя контракта, без домена и сертификатов. Основная среда на всё время разработки |
| Рабочая среда, тестовая среда | Вторая и третья среды, на сервере организации. Появляются на этапе В |
| Этап В | Внедрение на сервере организации. Выполняется при появлении сервера, ворота этапов 0–7 не блокирует |
| Пройти сценарий своими руками | Выполнить его в настоящем браузере из пустого состояния и записать наблюдаемые результаты по шагам (`11-ИСПОЛНИТЕЛЬ.md` § 3.1) |

## 3. Правила образования имён

| Что | Правило | Пример |
|---|---|---|
| Идентификатор в коде | camelCase, английский, по этой таблице | `affectedPerson` |
| Таблица и столбец | snake_case, английский | `affected_person`, `occurred_at` |
| Схема базы | Совпадает с именем модуля | `incident` |
| Код разрешения | `<модуль>.<объект>.<действие>` | `incident.card.close` |
| Код справочника | ЗАГЛАВНЫЕ_С_ПОДЧЁРКИВАНИЕМ, **без дефиса** | `INCIDENT_KIND` |
| Код элемента справочника | Заглавные с дефисом, **дефис обязателен** | `ZML-01` |
| Настройка и предел | ЗАГЛАВНЫЕ_С_ПОДЧЁРКИВАНИЕМ | `LIMIT_MEETING_CONCURRENT` |
| Компонент | PascalCase, английский | `SeverityBadge` |
| Экран | `Э-NNN` в документах, PascalCase в коде | `Э-101`, `IncidentCardScreen` |
| Приёмочный сценарий | `ПС-<этап>-<номер>` | `ПС-1-03` |
| Норматив | `Н-NN` | `Н-08` |
| Допущение | `Д-NN` | `Д-21` |
| Вопрос | `В-NNN` | `В-007` |
| Запись о решении | `adr/NN-краткое-имя.md` | `adr/11-otkaz-vmesto-pustogo-spiska.md` |

Различие в форме кода справочника и кода его элемента (подчёркивание против дефиса) — не украшение. На нём построена автоматическая проверка правила замещаемости `pnpm check:literals` (`00-КОНТРАКТ.md` § П-1).
