# 06. Гибридная карточка события: типизированное ядро и расширяемая часть

**Дата:** 2026-09-08
**Состояние:** принято

## Вопрос
Состав полей карточки ЧС нам неизвестен. Полностью динамическая форма делает аналитику невозможной; полностью жёсткая — ломается при первом же несовпадении с нормативной формой.

## Решение
Ядро карточки — типизированные столбцы: время, место, геометрия, погибшие, травмированные, пропавшие, пострадавшие, эвакуированные, спасённые, дома, скот, площадь, ущерб, силы и средства. Эти величины есть в учёте любой службы реагирования и нужны аналитике типизированными.

Дополнительные поля описываются в `incident.extra_field` для каждого вида события и хранятся в `extra` типа `jsonb`.

## Отвергнуто
- **Полностью динамическая карточка (только описание полей и значения)** — показатели нельзя посчитать без разбора значений, диапазоны и сортировка недоступны, нормативы производительности недостижимы.
- **Полностью жёсткая карточка** — не переживает Д-01.
- **Отдельная таблица на каждый вид события** — число таблиц растёт вместе со справочником, что противоречит принципу П-1.

## Последствия
Проще: аналитика работает по типизированным столбцам и укладывается в нормативы; новые поля добавляются администратором.
Сложнее: два способа хранения полей в одной карточке.
Платим: **фильтрация по дополнительному полю поддерживает только точное совпадение и наличие**. Диапазоны, сравнения и сортировка — только по полям ядра, потому что динамическое поле не может получить собственный индекс без изменения схемы.

## Условие пересмотра
Если по конкретному дополнительному полю систематически нужны диапазоны и сортировка — оно переносится в ядро отдельной миграцией. Это изменение контракта.
