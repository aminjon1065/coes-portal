# 16. Внутренний удостоверяющий центр и обязательная раскатка корневого сертификата

**Дата:** 2026-09-08
**Состояние:** принято

## Вопрос
Доменного имени и публично доверенного сертификата, скорее всего, нет. При этом браузер не выдаёт доступ к камере и микрофону без действующего HTTPS, а cookie с признаком `Secure` без HTTPS не работает.

## Решение
Внутренний удостоверяющий центр на основе openssl, создаваемый одной командой при установке. Корневой сертификат действует 10 лет, сертификат сервера — 825 дней. Установка корневого сертификата на рабочие места — **обязательный шаг внедрения**, описанный в `12-ЭКСПЛУАТАЦИЯ.md` § 3, а не примечание.

## Отвергнуто
- **Самоподписанный сертификат сервера без удостоверяющего центра** — потребовал бы установки нового сертификата на все рабочие места при каждом продлении.
- **Caddy или Traefik с автоматическим выпуском** — требуют публичного доменного имени, которого нет.
- **step-ca** — полноценная служба удостоверяющего центра ради того же результата: ещё один постоянно работающий процесс, который некому обслуживать.
- **Работа по HTTP** — камера и микрофон недоступны, `Secure` cookie не работает; неприемлемо.

## Последствия
Проще: одна команда при установке, продление сертификата сервера без повторной раскатки корневого.
Сложнее: раскатка корневого сертификата — организационный шаг, без которого система выглядит неисправной.
Платим: **внутренний центр не закрывает личные телефоны внешних участников совещаний**. К этапу 7 с высокой вероятностью потребуется доменное имя и публичный сертификат (Д-02).

## Условие пересмотра
Получение доменного имени — переход на публично доверенный сертификат для внешнего входа; внутренний центр остаётся для рабочих мест внутри контура.
