# 17. Двоичные объекты в файловой системе, а не в объектном хранилище

**Дата:** 2026-09-08
**Состояние:** принято

## Вопрос
Где хранить вложения, сканы, шаблоны и записи совещаний — до нескольких терабайт.

## Решение
Файловая система на медленном томе, путь по хешу содержимого. Метаданные — в `store.blob`. Одинаковое содержимое хранится один раз. Выдача — только через API с проверкой прав; прямой доступ nginx к каталогу хранилища отсутствует. Интерфейс `BlobBackend` развязан, чтобы замена была возможна без переделки модулей.

## Отвергнуто
- **MinIO** — сменил лицензию на сильный копилефт, что противоречит предпочтению разрешительных лицензий; на одном сервере не даёт ничего, кроме дополнительной службы и второго контура резервного копирования.
- **Хранение содержимого в базе данных** — раздувает базу, замедляет резервное копирование и восстановление, при терабайтах неприемлемо.
- **Раздача файлов напрямую через nginx** — обошла бы проверку прав; ссылка на файл стала бы ключом к нему.

## Последствия
Проще: резервное копирование файлов — обычная поблочная синхронизация; выгрузка записей совещаний на внешний носитель — обычное копирование.
Сложнее: выдача файла проходит через процесс приложения и потребляет его ресурсы.
Платим: раздача крупных файлов нагружает процесс API.

## Условие пересмотра
Появление второго сервера или требование раздавать файлы в обход приложения. Тогда добавляется выдача по подписанной ссылке ограниченного срока — без изменения хранилища.
