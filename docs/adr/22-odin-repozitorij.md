# 22. Один репозиторий

**Дата:** 2026-09-08
**Состояние:** принято

## Вопрос
Один репозиторий или несколько.

## Решение
Один репозиторий, рабочие пространства `pnpm`. Пакеты: `core`, `contracts`, `db`, `ui`, правила линтера; приложения: `api`, `worker`, `web`; каталоги `deploy`, `tools`, `docs`.

## Отвергнуто
- **Отдельные репозитории для сервера и клиента** — изменение контракта API затрагивает обе стороны одновременно; в разных репозиториях это два изменения, между которыми возможно расхождение. Ровно так документация разошлась с кодом в первой попытке.
- **Отдельный репозиторий для документов** — комплект обязан изменяться тем же изменением, что и код (`11-ИСПОЛНИТЕЛЬ.md` § 8).
- **Nx или Turborepo** — настроечная поверхность не окупается при трёх приложениях; обычные скрипты и `pnpm` достаточны.

## Последствия
Проще: атомарное изменение схемы, контракта, сервера, клиента и документов; одна команда проверки.
Сложнее: полная проверка выполняется дольше, чем в маленьком репозитории.
Платим: время `pnpm verify` растёт вместе с системой. Норматив на него не назначается: он не влияет на пользователя.

## Условие пересмотра
Не предполагается.
