# 02. TypeScript на обеих сторонах и общий пакет контрактов

**Дата:** 2026-09-08
**Состояние:** принято

## Вопрос
Как исключить расхождение между сервером, клиентом и документацией, если человека, сверяющего их, не существует.

## Решение
TypeScript в строгом режиме на сервере и клиенте. Схемы запросов и ответов описаны один раз в `packages/contracts`; из них формируются серверная проверка, файл OpenAPI и типизированный клиент. Типы базы данных генерируются из живой схемы. `pnpm check:generated` роняет сборку при расхождении сгенерированного с закоммиченным.

## Отвергнуто
- **Python (FastAPI) и React** — два языка, дублирование моделей, слабее гарантии на границе.
- **Go и React** — нет общих типов с клиентом; описание контракта пришлось бы вести отдельно.
- **Java или Kotlin (Spring)** — избыточный вес при потолке памяти 32 ГБ и 300 пользователях.
- **Ручное описание API в документе без генерации** — ровно тот способ, которым документация разошлась с кодом в первой попытке.

## Последствия
Проще: изменение контракта — одно изменение в одном месте, расхождение становится ошибкой сборки.
Сложнее: сгенерированные файлы хранятся в репозитории и требуют повторной генерации при каждом изменении.
Платим: связанность сервера и клиента одним языком; замена одной из сторон потребует переписывания пакета контрактов.

## Условие пересмотра
Появление второй системы-потребителя API, написанной не на TypeScript. Тогда OpenAPI остаётся, а генерация клиента выносится на её сторону.
